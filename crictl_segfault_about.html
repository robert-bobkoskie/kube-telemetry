Detection Logic

Primary Check: Live Crash Detection

Runs /usr/local/bin/crictl ps on each host via SSH and captures stdout+stderr.

  1. Strip ANSI escape sequences from combined output.
  2. Scan every line using this case-insensitive regex:

(sigsegv|segmentation\s+fault|segmentation\s+violation|segfault|signal\s+11|core\s+dumped|unexpected\s+signal\s+during\s+runtime)

If any line matches, the full crash block (including Go stack trace) is captured as evidence.

Secondary Check: Historical Crash Detection (dmesg)

After crictl ps, runs dmesg | grep -i segfault | grep -i crictl to find past crashes since boot.

This catches segfaults that occurred between cron runs—even if crictl ps works fine now.

Evidence is the kernel one-liner (fault address, instruction pointer, binary name).

Benign Output Handling

The expected FATA[0000] load config file: ...crictl.yaml: no such file or directory message is classified as OK using:

load\s+config\s+file:.*crictl\.yaml:.*no\s+such\s+file\s+or\s+directory

Alerting and History Across Runs

  • crictl_segfault_report.html: rolling dashboard (regenerated each run).
  • crictl_segfault_alert_latest.html: alert page showing live + historical segfault evidence.
  • crictl_segfault_timeseries.csv: persistent multi-run history, append-only unless rotation occurs.
  • crictl_segfault_alerts.log: one log line per segfault run with run timestamp and affected hosts.

With --fail-on-segfault, process exits code 2 when any host is FAIL_SEGFAULT.

Common CLI Options

  • --elevate-mode none|sudo|su|toor: choose one elevation strategy for the entire run. Also used for the dmesg secondary check.
  • --no-fallback: disable fallback command candidates and run only --command.
  • --fail-on-segfault: return exit code 2 when a segfault is detected.
  • --latest-segfault-alert <path>: set the single overwritten segfault alert HTML path.
  • --rotate-max-rows N: rotate CSV when row count reaches N; use 0 to disable rotation.
  • --help: show full argument help and defaults.
